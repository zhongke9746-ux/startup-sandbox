# 实地沙盒 · 规则规格 v0.1

> 一个以**真实世界信息截面**为输入、由 AI 智能体自主运营、输出可审计可行性判断的创业模拟系统。
> 本目录存放的是**规则层规格**——它先于代码存在，也是代码的唯一依据。

## 一、这个系统不做什么

先把边界钉死，否则规则会越写越散：

| 不做 | 原因 |
|---|---|
| 不预测未来 | 沙盒输出的是"在创建时刻已知信息下，这个项目会怎么演化"，不是预言 |
| 不追求"真实世界全息复刻" | 只处理**已数字化、可被抓取、可被语言模型解析**的那一部分现实 |
| 不让 AI 自由发挥影响量级 | 所有冲击的量级必须有规则来源，AI 只在规则给定的区间内判定取值 |
| 不给"是/否"的单一答案 | 输出是失败模式 + 脆弱变量 + 分项评分，最终判断权仍在创业者手里 |

## 二、四层架构

```
┌─────────────────────────────────────────────────────────┐
│ L0 采集层   DeepSeek Search/Fetch（before: 日期围栏）      │
│             + localization（项目所在地）+ authority≥3     │
└────────────────────────┬────────────────────────────────┘
                         ↓ 信号（Signal）
┌─────────────────────────────────────────────────────────┐
│ L1 冻结层   只读快照：信号库 + 结构化参数 + RAG 知识库      │
│             创建时刻 as_of 之后的信息物理不可见            │
└────────────────────────┬────────────────────────────────┘
                         ↓ 冲击（Impact）
┌─────────────────────────────────────────────────────────┐
│ L2 引擎层   确定性结算：状态变量 × 冲击 × 时间衰减         │
│             月度心跳：结算 → 熔断检查 → 快照检索 → 决策    │
└────────────────────────┬────────────────────────────────┘
                         ↓ 轨迹（Trajectory）
┌─────────────────────────────────────────────────────────┐
│ L3 评估层   生存 / 单位经济 / 合规韧性 / 增长 / 资本效率   │
│             + 因果链审计日志 + 失败模式归因                │
└─────────────────────────────────────────────────────────┘
```

**关键设计：L2 是确定性的，不是让 LLM 自由演。** LLM 只在两个位置出现——判断"这条信号打到哪个变量、量级落在规则区间的哪一档"（L1→L2 的翻译），以及扮演经营角色做决策（L2 内部）。所有数值结算由代码按公式完成，这样同一组输入必然得到同一组结果。

## 三、规则的三层判定

一条信号进入系统后，走三道关卡：

1. **规则匹配（确定性）**：信号的 category + 关键词 + 来源权威度 → 命中预置规则包（如 `R-POL-01`）。命中即获得一个"影响模板"。
2. **语义判定（LLM，受限）**：LLM 读原文，在模板给定的区间内选档——比如模板说"合规成本 +18%~35%"，LLM 根据政策严厉程度选 22% 还是 31%，并给出原文依据。**它不能超出区间。**
3. **引擎结算（确定性）**：按公式把冲击写进状态变量，记录审计条目。

这个设计的用意：把"AI 的判断力"约束在"在给定框架内做取舍"，而不是"自由发明影响"。这是沙盒可信度的底线。

## 五、跑起来

### 应用版（推荐）

```bash
python3 scripts/server.py        # → http://127.0.0.1:8877
```

零第三方依赖（纯 Python 标准库），浏览器里完成：开局填表（地点/资金/面积/客源/实测会员数/快照）
→ 决策点选动作 → 实时账本曲线 → 经营评估报告（异步任务）→ 反事实审计。
数据全部落在本地 `sessions/*.json`，深链 `#sid=会话名` 可直达某局。
前端是单文件 `web/index.html`，无框架无构建。

### 命令行版

```bash

    --snapshot snapshots/cafe-2026-11-16.json              # 用真实抓取的环境快照开一局
python3 scripts/session.py new cafe --seed 42 --name 我的店 \
    --intake 我的采集表.json --snapshot snapshots/xxx.json # 你的参数 + 真实世界（完整形态）
```

## 六点四、资金口径：现金 ≠ 净资产（2026-11-17 修正）

原模型只有「现金」和「预收负债」两个账户，导致三个错：
开业投入没进账（20 万现金 + 8 万转让费，那 8 万凭空消失）、
退出变现按一个拍脑袋的比例、回报率的分母用了「账上现金」而不是总投入
（于是算出 500% 的年化）。

现在三个账户并行，两个口径分开报：

| 口径 | 公式 | 回答什么 |
|---|---|---|
| 净现金 | 现金 − 预收 | 明天会不会断粮（流动性） |
| 净资产 | 现金 + 资产 − 预收 | 我投的钱现在值多少（投资） |

资产按四项记：转让费（不折旧/退出 50%）、装修（摊 36 月/退出 25%）、
设备（摊 60 月/退出 30%）、押金（不折旧/退出 95%）。**折旧不进利润表**，
所以「净利」是现金流口径；净资产变化 = 现金变化 + 折旧 + 预收摊销，两者别混。
退出（A-STR-02）现在会：按分项残值变现 + 退还预收 + 关店停止固定成本。

## 六点五、分发（打包给别人用）

```bash
ruby scripts/yaml2json.rb      # 改过 rules/ 才需要；没改可跳过
python3 scripts/pack.py         # 产出 dist/创业沙盒-<日期>.zip
```

包里只放跑起来需要的东西：运行时 6 个 Python 模块、预编译好的 `build/*.json`、
`rules/*.yaml`（留给想改的人）、`web/index.html`、两个快照、三个示例会话，
外加 `start.py` 与两个双击启动器（macOS `.command` / Windows `.bat`）。
开发脚本和十几份设计文档不进包。

三条约束，改分发逻辑时别破坏：

1. **收包的人不需要 ruby**。`build/*.json` 随包分发；`engine.build()` 发现 json 齐全
   就直接用，只有 json 缺失或显式 force 才去调 ruby。
2. **不能出现本机绝对路径**。`pack.py` 打完会扫一遍 `/Users/edy`，命中就中止。
3. **启动要能双击**。`.command` 必须以 0755 写进 zip（`pack.py` 手动设 external_attr），
   否则收到的 Mac 双击只会得到"无法打开"。

对方只需要系统自带或一次装好的 Python 3.7+，不联网、不装依赖、不注册账号。

规则里的每个数字都是**可辩论的假设**，不是事实。它的价值不在于"算得准"，而在于"把假设摆到台面上，让你看见自己在赌什么"。改动任何量级，都要在 YAML 里留版本号和改动理由——这套规则的历史比它的当前版本更重要。
